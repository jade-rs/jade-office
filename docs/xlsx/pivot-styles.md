# Pivot styles and standard worksheet ownership

The later [refresh fitting checkpoint](pivot-autofit.md) adds automatic column
width updates and typed report-filter geometry. Its counts and source hashes
supersede the historical style-only totals below; full style coverage remains open.


Imported, explicitly named PivotTable styles now reach the shared grid layout,
including unstored cells. The same overlay follows refreshed report locations;
it is not baked into the report's cell formats. Both application shells use
this layout. The implementation supports custom definitions and the 84 normative
`PivotStyleLight1–28`, `Medium1–28` and `Dark1–28` definitions.

## A real workbook corrected the ownership model

The unmodified ECMA-376 Part 1 (2016) `PivotTableFormats.xlsx` contains 22
PivotTables. Its worksheets own tables through internal relationships of type
`…/pivotTable`; they have no `pivotTableParts` worksheet elements. The prior
reader expected these fictional declarations and exposed zero tables. The
standard CT_Worksheet schema has no such declaration list.

The reader now follows direct, correctly namespaced worksheet relationships,
checks internal target/type/identity, and rejects ambiguous ownership. Workbook
cache declarations remain `pivotCaches/pivotCache`. MCE tests now exercise
those real declarations. Foreign relationship parents cannot promote a pivot
link. An owned table with an unresolved workbook cache retains workbook-level
source uncertainty, so structural source edits cannot silently invalidate it.

The historical Jade `pivot-cache-compat.xlsx` fixture contains nonstandard
worksheet markers. It remains unchanged for reproducibility; passing its older
marker tests did not prove standard worksheet ownership. New reader cases and
the styled Jade fixture exercise relationships without those markers. This
correction supersedes the worksheet-declaration account in older checkpoints.
The normative workbook is producer evidence for ownership and legacy formatting;
it is not an oracle for every report layout or style.

## Styles and precedence

Only owned `styleSheet/dxfs/dxf` and `styleSheet/tableStyles/tableStyle` collections
supply custom definitions. Foreign/extension wrappers cannot promote nested
formats. Empty differential entries retain their index. Gallery availability
flags and `defaultPivotStyle` are retained. A creation default does not restyle
an existing report whose saved style name is absent or empty.

Pivot region precedence is separate from ordinary table precedence. The overlay
uses row/column axes and compressed prefixes to identify headers, row labels,
stripes, subtotal/subheading levels, blank rows and grand totals. It resolves
colors against each workbook's theme. Explicit cell fills and explicitly applied
fonts take priority; conditional formatting can override both. Unstored report
cells keep their surface, and bounded report extents contribute to layout axes.
Malformed or excessive automatic-style geometry is skipped without allocating a
whole-sheet grid.

The unmodified normative preset XML uses **zero-based pivot dxf indices**. The
ordinary table definitions in the same file use one-based indices; the pivot
loader does not reuse that indexing rule. A regression checks Medium9's actual
header color and white text, and confirms that its body is not incorrectly
filled. A separate case checks all 84 names resolve, which is not 84 visual
oracle comparisons.

The independent implementation uses unmodified Ecma data with a
[provenance record](../../jade-core/crates/jade-xlsx-layout/data/presetTableStyles-provenance.json)
and [copyright notice](../../jade-core/crates/jade-xlsx-layout/data/ECMA-NOTICE.txt).
No ibisOffice or Apache implementation code is incorporated. Byte offsets and
the original Jade styled fixture are reproducibly generated by
[the index script](../../scripts/xlsx/generate_pivot_style_offsets.py) and
[the fixture script](../../scripts/xlsx/generate_pivot_style_fixture.py).

## Validation boundaries

Reader cases cover the unmodified 22-table workbook, standard implicit ownership,
custom collection namespaces/hierarchy and positional differential identities.
Layout cases cover explicit/custom/builtin styles, theme isolation, omitted
flags, creation defaults, compressed axes, stripes, conditional priority,
unstored/extending cells and bounded invalid geometry. Native raster sampling
checks blue headers, yellow manual fills, red unstored cells and green totals.
A shared TinySkia model case grows a report, checks the old total becomes a body
row, preserves manual formatting, reopens the result and verifies Undo/Redo in
actual pixels. Refresh may legitimately append number-format XFs; existing XFs
and the custom style collections must retain their identity.

Full styling remains incomplete: page-field areas outside the saved report
location, all nested/tabular grouping border spans, complete differential font/
number-format/pattern/gradient properties, style-family MCE, standalone
`layout_sheet` calls without workbook context, and Office save/repair/visual
oracles across all presets/layouts need further work. Autofit, PivotChart binding
synchronization, pivot authoring, grouping/calculated/show-as/OLAP, slicers and
other [audit gaps](ibis-parity.md) remain open. This does not establish full
ibisOffice parity.

Primary semantics: [ECMA-376 normative files](https://ecma-international.org/publications-and-standards/standards/ecma-376/),
[PivotTable style precedence](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.spreadsheet.tablestyleelement?view=openxml-3.0.1),
[creation defaults](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.spreadsheet.tablestyles?view=openxml-3.0.1).
