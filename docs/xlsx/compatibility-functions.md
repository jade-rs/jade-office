# XLSX compatibility calls and formula behavior

The engine now exposes 507 English function names, compared with 512 in the
[pinned ibisOffice inventory](ibis-function-baseline.json). The actual engine
inventory is [jade-function-inventory.json](jade-function-inventory.json), and
[function-diff.json](function-diff.json) is generated by
`scripts/xlsx/compare_functions.py`. Registration is not a claim that every
function/argument/locale case matches Excel.

## Implemented compatibility calls

| Name | Behavior and saved spelling |
|---|---|
| `GETPIVOTDATA` | Queries saved visible pivot results with real workbook context, field/item aliases, typed/date criteria and array broadcasting; stored bare. See [scope and structural editing](getpivotdata.md) |
| `ECMA.CEILING` | Two-argument CEILING arithmetic, including sign/zero/precision/error handling; stored bare as specified by the XLSX function table |
| `SINGLE` | Lowers to implicit intersection, like the saved `_xlfn.SINGLE` representation of `@`; arrays use their top-left item, ranges use the caller's row/column on the referenced sheet, and scalars/errors preserve their type |
| `ANCHORARRAY` | Lowers to the existing spill-range operator, like `_xlfn.ANCHORARRAY`/`#`; follows dynamic spill growth/shrinkage through evaluation, save/reopen and history |

The pinned reference [math implementation](https://github.com/ibisjp/ibis-office/blob/6e004f71ed43ea73c1a6cb0f0496483c107a0485/crates/ibis-calc/src/functions/math.rs)
groups ECMA.CEILING with CEILING.PRECISE, including an optional significance
and absolute-sign behavior. Jade uses the two-required-argument, signed
significance behavior described for ECMA.CEILING in ISO/IEC 29500 and the
corresponding CEILING examples. This difference is explicit; registration
counts alone are not a claim of identical semantics. The pinned
[lookup implementation](https://github.com/ibisjp/ibis-office/blob/6e004f71ed43ea73c1a6cb0f0496483c107a0485/crates/ibis-calc/src/functions/lookup.rs)
was inspected for SINGLE/spill operand behavior. No implementation code was
copied.

Before this change, the prefixed operator names had parser support but were
absent from lookup/prefix metadata and the inventory. Bare/case-varied calls
were incomplete, and removing display prefixes could leave imported calls
unrecognized during calculation projection. The new names have real registry,
argument-count, file-prefix and evaluation paths. Valid operator calls keep
the operator AST; invalid arities use the ordinary argument-count error so
shared typed input rejects them without overwriting the previous cell.
Lambda names bound with `_xlpm.` remain bindings rather than builtin calls.

The shared CEILING arithmetic now broadcasts numeric operands over arrays
and scalar/singleton dimensions, retaining element errors. It uses the
engine's existing one-million-cell output matrix limit; oversized broadcasts
return the engine's limit error rather than allocating the full output. That
resource limit is not an Excel equivalence claim. The size product is
saturating for the browser's 32-bit target. Other scalar math functions still
need their own array cases.

The intersection fix also removes a larger-array scalar-context assertion,
preserves top-left number/string/boolean/error types, and permits cross-sheet
row/column intersection. It returns a value from a multi-cell range, not a new
reference object. An initial ISREF test assumed reference-type output; that
assumption was corrected after checking the Microsoft description and the
LibreOffice SINGLE implementation. This was a test-expectation correction,
not a relaxed assertion used to claim extra reference semantics. One-cell
reference/type edge cases still need Excel captures.

## FORMULATEXT follow-up

The engine regression exposed an old unimplemented `FORMULATEXT(@range)`
expectation. Its reference signature is now kept intact for ordinary ranges,
whose top-left cell supplies the formula. A scalarized operand or other invalid
scalar type returns VALUE; a cell without a formula returns NA. The 8192 UTF-16
unit boundary is checked, and self-reference can report its own formula text.
The prior stub assertions now verify actual top-left formulas and the explicit
scalar error, with separate integration cases. Normalized English formula text,
source whitespace, hidden/protected formulas, non-BMP length boundaries and
other imported cases still need Office comparison; this does not certify the
entire FORMULATEXT feature.

## Evidence and remaining names

Thirteen integration scenarios cover sign/precision/coercion, scalar/array/range
intersection, cross-sheet calls, prefix/case/arity, inventory, imported stale
caches, spill sizing and growth/history, circular references, lambda shadowing,
broadcast/error/resource cases and FORMULATEXT boundaries. The shared-model
typing scenario covers accepted calls, refused arities, rejected-entry history,
spills and save/reopen. Full core/engine/compile results are recorded in
[verification.md](verification.md).

`FILTERXML` is registered now (an XPath subset: element paths, `*`, `//`,
`@attribute`, `text()` and `[n]`, `[last()]`, `[@a]`, `[@a='v']`, `[child='v']`
predicates), and `GROUPBY` (row fields, a LAMBDA or a function named bare,
headers, a grand total at either end, sorting and a filter; subtotal depths
above one not yet). The three remaining registration differences are
`IMAGE`, `PIVOTBY` and `WEBSERVICE`. Their calculation, workbook/object
context or external-service requirements are not filled with placeholder
registry entries. Pivot tables, connections, advanced charts, protection and
other [audit areas](ibis-parity.md) remain part of the active parity goal.
Non-array anchors and invalid operands return REF; source errors and cycles
propagate, and the source is evaluated before its shape is queried. One-cell
dynamic arrays remain valid anchors. Classic CSE and other spill boundaries
still need application captures.

Manual native interaction and Excel repair/save/calculation/pixel captures
remain outstanding.

## Vendored source provenance

`jade-core/third_party/ironcalc-base/jade.patch` was regenerated from the
hash-verified official IronCalc 0.8.3 crate. The reusable
[scripts/xlsx/replay_engine_patch.py](../../scripts/xlsx/replay_engine_patch.py)
verifies the archive/provenance hashes, applies the patch once and compares all
489 current source/build files byte for byte. It can regenerate the patch with
`--update`; the upstream hash inventory remains unchanged. Final compilation
and tests use the actual engine/core manifests and lockfiles.
